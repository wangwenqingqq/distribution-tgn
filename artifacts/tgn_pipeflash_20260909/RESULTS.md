# PipeTGL + FlashTGN 首轮原型与验证

首轮原型已实现。受控对照表明，直接替换批内算子能带来部分收益，但完整进程收益较小，双卡在本机配置下还出现退化。当前结果支持继续研究状态、通信与准备开销的联合调度，尚未证明可发表的新系统贡献。

## 受控对照

Wikipedia，1 层，fanout=10，D/time-D=100，2 heads，batch=600，dropout=0，FP32 highest。种子为 2026、2027、2028，每次 3 个训练 epoch，加原入口的一次预热优化。两版均采用完整末批、确定性最后事件写回、Gloo 阶段 barrier；保留原来的 per-rank Adam、参数陈旧及 sqrt(P) 学习率缩放。

每个 epoch 和预热均实际处理 110,232 条正样本边，包括最后 432 条，所有 rank 汇总计数均通过。18 次运行全部正常退出。GPU 为 RTX PRO 6000 Blackwell；这里只使用同一主机的 1/2/4 卡。

| 卡数 | PipeTGL 校正版：完整进程秒 | 融合版：完整进程秒 | 完整进程加速比 | 原版/融合版全局 epoch 秒 |
|---:|---:|---:|---:|---:|
| 1 | 22.161 ± 2.286 | 20.742 ± 1.955 | 1.068× | 2.811 / 2.488 |
| 2 | 19.056 ± 0.941 | 19.607 ± 0.990 | 0.972× | 1.639 / 1.919 |
| 4 | 17.337 ± 0.200 | 16.637 ± 0.050 | 1.042× | 0.910 / 0.757 |

± 为三个种子间的样本标准差。表内加速比是两版均值之比；JSON 另存逐种子配对比值。每个种子的 epoch 数先平均，再跨种子统计，避免把三个连续 epoch 当作九个独立重复。

完整进程从启动 torchrun 到进程退出，包括导入、数据/图准备、描述符处理、预热优化、训练、验证、权重/memory 保存和退出。全局 epoch 使用单机共用的 perf_counter 时钟，取各 rank 最早开始到最晚 CUDA 同步完成；不是只取最长 rank 时间。训练 driver 的完整区间和各 rank 原始区间也保留在 JSON。跨主机不能直接复用此时钟方法。

## 数值与状态核对

- 初始参数的五类图：空邻居、混合度、满 fanout、大量空查询，以及最大约 267 万秒的时间差，输出和梯度均通过。
- 使用训练后的两份权重，在 10,000 秒和约 267 万秒两种时间差下，输出、输入梯度、边特征梯度及所有参数梯度也通过。
- GPU 检查固定 atol=5e-5、rtol=4e-4，没有因失败放宽阈值；最终学习后参数测试的最大输出误差约 1.31e-6。
- 九组同种子/同卡数配对，初始 rank-0 权重逐元素一致；最终 node-memory 时间戳和 mailbox 时间戳逐元素一致。
- 最终浮点权重并不逐元素一致。上述检查不等于确定性重放、每批完整梯度等价或顺序 Adam 等价；跨 rank 参数陈旧协议保留。

## 为使结果可比而做的修正

1. 原入口先取下一批、遇到 EOF 就退出，漏掉最后一个本地批次。受控模式会处理当前末批，并同时调整 feature I/O 次数和通信终止条件。
2. 重叠节点预计算原先按固定 2×batch 大小截取；不足一批时会纳入负样本。现在按 2×len(eid) 取正样本端点。
3. 原三个 memory 更新方法用重复索引 scatter_ 选写回位置。受控模式将六处选择改为整数事件位置的 amax，显式规定最后事件写回。该行为修正同时用于原版和融合版，原始代码快照保留。
4. 原多卡入口在本软件栈发生预热出口阻塞。阶段同步改为 Gloo 控制 barrier，GPU 数据和参数传输仍使用 NCCL。该结论限于本机软件栈，不代指论文原实验环境。
5. Flash 原快照的 fast math 在大时间差下未通过数值测试。单独关闭 fast math 后，非零学习 bias 的乘加舍入仍不同。最终独立 gather 扩展使用精确三角函数和显式 FMA，匹配已探测的原 FP32 线性时间编码。Flash 原始快照及其扩展没有被覆盖。

这些兼容和行为修正用于建立可审查的对照，不自动构成论文创新。被淘汰版本的失败日志、数值结果和运行记录全部保留，并有 status 文件说明；性能主表仅使用 stable campaign。

## 阶段观测与测量边界

双卡和四卡两版的 CPU 函数区间均已独立采集，并导出 Chrome trace JSON。前向函数的 CPU 提交区间缩短，构建/传输描述符的区间增加。CPU 提交区间含阻塞、嵌套和异步调用，不能直接解释为 GPU 计算时间，也不能把这些区间相加当作完整关键路径。

完整 CUDA Nsight tracing 在一次融合版双卡采集中触发阻塞，该记录被归类为失败诊断，不作为性能数据。普通训练及不拦截 CUDA 的主机时间线运行成功。单卡 CUDA 内核时间线单独采集；GPU 活动并集、SM active 和依赖等待是不同指标，本轮没有把任何一种直接命名为 pipeline bubble。

单卡 CUDA 诊断中，原版/融合版 epoch 为 3.442/2.801 秒，GPU 活动区间并集为 0.3034/0.3027 秒；GEMM 类内核累计约 0.0644/0.0613 秒，约占各自 profiled wall 的 1.9%/2.2%。这提示优先研究 GPU 活动之间的主机提交与同步间隙。内核名称归类只是近似，profiled wall 含采集开销，不能据此计算正式 STC 加速上界。详见 analysis/stable_single_gpu_activity_summary.json。

本轮尚未把多卡关键路径上的通信传输与依赖等待可靠分开，因此没有给出 Figure 15 的 bubble 复现值，也没有以 1-GPU 利用率估算 bubble。

## 下一阶段的研究判断

优先验证有限批次、阶段波动、host 准备和通信资源约束下的调度模型，量化缩短前反向后哪些等待暴露出来。直接适配版仍存在每批描述符构造、掩码压紧和中间缓冲区开销，后续优化可从状态提交与紧凑描述符的衔接入手。流水线宽度选择必须在固定语义批次、明确参数/状态版本规则下比较。

本轮没有接入 STC：当前算子的图/邻居稀疏不等于 2:4 结构化权重稀疏，尚无证据证明压缩、反向和精度成本计入后能缩短多卡关键路径。只有测得相关矩阵运算是主要限制后再启用这一分支。

## 适用范围与复现

- 单一 Wikipedia、B600、1 层、3 种子、3 epoch，是初步系统实验；尚未覆盖 B2000、2 层、其他数据集、8 卡或多主机。
- NCCL_P2P_DISABLE=1、NCCL_IB_DISABLE=1、NCCL_SOCKET_IFNAME=lo。此前本机直连 P2P 检查发现数据损坏，因此这些结果不能外推到经过验证的 GPUDirect/NVLink 环境。
- 共享主机上每次都检查目标 GPU 空闲并持有现有 advisory locks；没有停止其他任务。CPU/系统不是整机独占。
- 这里比较的是 PipeTGL 原算子路径与其融合算子适配版。FlashTGN 原系统只完成过短训练执行检查，不能由本表推出超过 FlashTGN 单卡系统或当前所有系统。
